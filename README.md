# 打卡系统 · 服装生产跟单打卡系统

公司内部使用的生产进度跟踪工具，替代 Excel 表格手工记录订单进度的方式。

下厂员在工厂现场随时打卡记录工序进度，业务员和管理员**在各自的手机/电脑上同时看到最新情况**，减少电话沟通和手工登记表格的成本。

- 手机、电脑都能正常使用（响应式设计）
- 真正的服务端 + 数据库，多人多设备共享同一份数据
- 界面：简洁商务风，主色调韩式蓝（参考大韩航空）

---

## 快速开始

需要 **Node.js 22 或更高版本**（用到了 Node 内置的 `node:sqlite`，无需安装数据库）。

```bash
git clone https://github.com/HuangREPUBLIC/daka-system.git
cd daka-system
npm install
npm start
```

浏览器打开 <http://localhost:3000> 即可。

首次启动会自动建库并填充演示数据，演示账号（密码均为 `123456`）：

| 角色 | 手机号 |
|---|---|
| 管理员（老板） | 13800000000 |
| 业务员 | 13811112222 / 13833334444 |
| 下厂员 | 13855556666 / 13877778888 |

> **正式启用**：跑一条命令清掉演示数据，只留你自己的管理员账号：
>
> ```bash
> npm run init-admin -- --name 你的姓名 --phone 你的手机号
> ```
>
> 默认初始密码 `123456`，登录后请到「我的」里立刻改掉（也可以加 `--password 自定义密码`）。
> 想保留已录入的订单就再加 `--keep-orders`。

### 让手机也能访问

同一个 WiFi 下，用电脑的局域网 IP 访问即可，例如 `http://192.168.1.10:3000`。
（macOS 查看 IP：`ipconfig getifaddr en0`）

放到公司服务器上长期运行，推荐用 pm2：

```bash
npm install -g pm2
pm2 start server/index.js --name daka-system
pm2 save && pm2 startup
```

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 服务端口 |
| `DATA_DIR` | `./data` | 数据目录（SQLite 数据库 + 上传的款式图），部署时可指向独立磁盘/数据卷 |
| `JWT_SECRET` | 自动生成并保存在 `DATA_DIR/.jwt_secret` | 登录令牌密钥 |

> **备份**：把 `DATA_DIR` 整个目录复制走即可，里面就是全部数据。

## 角色与权限

权限全部在**服务端**强制校验（前端只是隐藏按钮，改不了实际权限）。

| | 管理员 | 业务员权限 | 下厂员权限 |
|---|---|---|---|
| 查看所有订单 | ✅ | ✅ | ✅ |
| 新建订单 / 批量导入 | ✅ | ✅ | ❌ |
| 修改订单基本信息 | 全部 | 仅自己录入的 | ❌ |
| 生产工序打卡 | 全部 | ❌ | 仅自己负责的订单 |
| 修改/删除打卡记录 | 全部 | 仅自己的 | 仅自己的 |
| 创建/删除员工、改职位、增减职位 | ✅ | ❌ | ❌ |
| 增减自定义字段 | ✅ | ❌ | ❌ |
| 导出 Excel | ✅ | ❌ | ❌ |
| 一对一私聊 | ✅ | ✅ | ✅ |

说明：

- 一个订单由**一个下厂员**从面料到包装全程负责；别人的订单只能看，不能打卡。
- 业务员可以更新「订单明细」板块里的面料进度、绣印进度。
- **管理员可以用下拉菜单直接修改任何人的职位，但不能修改自己的职位**；管理员账号不可被删除。
- **职位可以自定义**：除内置的「业务员」「下厂员」外，管理员可以新增职位（如「跟单主管」「质检员」），新增时选一套权限模板（业务员权限 / 下厂员权限），因此不会出现权限真空。还有人担任的职位不能被删除。
- 删除员工是软删除：账号无法再登录，但其历史打卡记录仍完整保留。离职后手机号可以重新用于新账号（返聘场景）。

## 主要功能

1. **登录**：手机号 + 密码，无短信验证码。忘记密码可用手机号直接重设。
2. **管理后台**：创建员工、下拉改职位、重置密码、删除员工（二次确认）。
3. **订单列表**：按季节 / 业务员 / 下厂员 / 货号款式名搜索筛选，卡片显示最新一条打卡。
4. **订单详情**：四大板块 —— 一、订单明细　二、生产明细　三、验货问题　四、跟单问题。
5. **打卡**：进度类字段像日志一样一条条往下加，**自动记录打卡人姓名和时间**，时间倒序排列，可回看每天情况。加工厂明细支持主厂 + 加工厂2/3/4 各自独立打卡。
6. **款式图**：支持上传图片，保存在 `DATA_DIR/uploads`。
7. **批量导入**：把 Excel 另存为 CSV 后上传（或直接粘贴表格内容）。识别后会**把内容填入可编辑表单**，逐项确认修改后再导入，不会直接入库。
8. **导出**：管理员一键导出全部订单为真实 `.xlsx` 文件。
9. **自定义字段**：管理员可在「订单明细」「生产明细」里增减字段，不是写死的固定表单。字段类型支持文本 / 进度打卡 / 日期 / 数字 / 下拉菜单。
10. **季节**：按当前中国时间自动生成 SS/FW 选项（上一年至后两年），新建订单和列表筛选都用同一份选项。
11. **一对一私聊**：像微信一样选联系人聊天，只有你们两人能看到。**支持发图片和文件**（jpg/png/pdf/Excel/Word/zip 等，单个 20MB 以内）。未读消息在 Tab 上显示红点，进入会话自动标记已读（4~10 秒轮询，规模小无需 WebSocket）。
12. **打卡记录**：在「我的账号」里查看自己的全部打卡；管理员可在「管理后台」点员工的「查看打卡」查看任何人的记录。

## 界面

- **移动优先**：底部 Tab 栏（订单 / 聊天 / 管理 / 我的），屏幕宽于 820px 时 Tab 栏自动移到顶部
- 参照 iOS 的分组列表（inset grouped）、系统字体、44px 触摸目标、大圆角与毛玻璃标题栏
- 日期一律显示中文「2026年8月15日」，打卡时间显示「7月19日 17:30」
- 日期和文件选择都用中文按钮包了一层（浏览器原生控件会显示英文 Choose File 和 yyyy/mm/dd），
  底层仍是原生控件，手机上照样调起系统日期轮和相册
- 主色沿用韩式蓝；自动适配深色模式
- 纯 CSS 实现，没有引入任何 UI 框架，因此无需构建步骤

## 登录状态

登录后签发的令牌**不设过期时间**，只要不主动点「退出登录」就一直保持，手机上不用反复登录。
账号被管理员删除时会立即失效。

## 技术栈

- **后端**：Node.js + Express，SQLite（Node 22 内置 `node:sqlite`，零原生依赖）
- **认证**：bcrypt 密码哈希 + JWT
- **前端**：原生 HTML/CSS/JS 单页应用，无需构建步骤
- **Excel**：SheetJS（使用官方 CDN 发行版，`npm audit` 无漏洞）

### 目录结构

```
scripts/
  init-admin.js  正式启用前清空演示数据、创建管理员
server/
  index.js    Express 启动、静态资源、SPA 兜底
  db.js       SQLite 建表与演示数据
  auth.js     密码哈希、JWT、登录中间件、权限判定
  routes.js   全部 API 路由
public/
  index.html  页面骨架
  app.js      前端全部逻辑
  styles.css  样式（韩式蓝，支持深色模式）
test/
  run.js      测试入口（临时数据库+随机端口，不影响正式数据）
```

### 数据存储

- `users` 账号表；手机号仅在**未删除**账号之间唯一（软删除后可重新启用）
- `settings` 键值表，存自定义字段、工厂下拉选项、职位定义
- `messages` 私聊消息（发送人、接收人、内容、时间、已读时间）
- `orders` 每个订单一行，业务数据以 JSON 存储；时间统一为毫秒时间戳
